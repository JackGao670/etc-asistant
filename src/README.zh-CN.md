# Embedded Communication Toolkit 0.1.8

[English](README.md) | 简体中文

开发者：常州竟锋软件有限公司

面向 VS Code 的本机通信调试工作台，当前为 MVP 开发候选版。
尚未完成公开发布到 Marketplace 所需的认证。

## 功能

- 串口：枚举及手动输入路径、波特率、7/8 数据位、校验、停止位、DTR/RTS 和 RTS/CTS。
- TCP 客户端及 TCP 服务端：服务端最多支持 16 个客户端，明确选择发送目标或确认后广播。
- IPv4 UDP：保留来源和数据报边界，显式启用广播，可配置发送载荷上限。
- 最多 8 个会话，支持 HEX/7 位 ASCII、时间戳、RX/TX 计数和虚拟化数据预览。
- 有界串口发送队列、超时清理及交付结果未知提示。
- 可选的 TCP 客户端自动重连，以及具备唯一身份的串口设备自动重连。
- 自动发送采用上次发送完成后延迟调度；连接断开后停止自动发送。
- 快捷命令，可选危险操作确认。
- 显式保存项目 `.vscode/ect.json` 配置，包含版本校验及覆盖检查。
- 无工作区时使用扩展 `globalState` 保存配置；多根工作区会提示选择所属目录。
- JSONL 原始录制独立于预览，包含有界全局队列、文件轮转、容量预算及不完整标记。
- 停止录制后可流式导出 TXT/CSV，并防止 CSV 公式注入。

## 工作台布局

0.1.8 将 TCP 服务端发送目标选择移到发送区。只有一个已连接客户端时默认选中；
多个客户端时必须明确选择目标，广播仍需确认。没有有效目标时，不能启动手动发送、
快捷命令发送或自动发送。明确选中的客户端断开后，不会静默替换为其他客户端。

0.1.6 将“会话”标签单独放在上方，下方同一行包含会话选择、打开、关闭、删除、
自动重连及状态控件。下拉框、操作按钮和状态标签统一为 30px 高度；
窄窗口中该行可横向滚动，控件不会换行。

0.1.5 使用当前 VS Code 主题统一输入框、下拉选项和串口弹层的颜色。
原生控件深浅模式跟随 VS Code 的浅色、深色及高对比度主题类；
串口悬停颜色和接收区底色不再混用按钮及代码块背景色。

0.1.4 增加从 300 到 2000000 的 21 个常用波特率预设，默认选中 115200。
其他速率可选择“自定义波特率”，输入 1 至 3000000 之间的整数；
实际支持的速率取决于设备和驱动。

0.1.3 将原生串口 `datalist` 弹窗替换为锚定在输入框下方的页面内下拉列表，
避免 Webview 原生弹窗位置偏移。支持手动输入路径、方向键选择、Enter 确认、
Escape 关闭及点击外部关闭。“刷新串口”会更新选项列表。

0.1.2 借鉴 uplume 的 Serial Tool - Serial Port Monitor 布局：
顶部为连接参数，左侧为接收日志，右侧为发送内容和快捷命令，底部为计数及显示选项。
窄窗口中接收区与发送区上下排列。ECT 保留 Serial/TCP/UDP 多会话模型，
并非复制 Serial Tool 的全部功能。

接收 HEX/ASCII 显示格式与发送 HEX/ASCII 编码独立设置。
搜索仅过滤显示文本，即每条记录的前 256 字节；“显示 TX”和时间戳仅影响预览，
不会改变原始录制。当前候选版尚未实现分组预设、可拖动分隔栏、CRC 及吞吐速率控件。

## 使用

安装 Windows x64 VSIX 后，执行 `ECT: Open Communication Workbench`
（中文命令为“ECT: 打开通信工作台”）。
也可点击活动栏中的通信图标，再点击空“连接”视图中的“打开通信工作台”按钮，
或使用该视图标题栏中的常驻入口。

侧栏显示会话列表，主通信界面在编辑器面板中打开。
创建会话后选择该会话，并明确点击“打开”。已保存的配置不会自动打开设备或发送数据。
关闭工作台面板后，会话、自动发送及录制仍继续运行；
关闭会话、执行“断开全部连接”或停用扩展会停止相关活动。

录制和导出通过 VS Code 对话框选择本地文件。目标必须是新文件，
现有日志不会被静默覆盖。导出会先停止录制，且拒绝导出标记为不完整的源记录。

## 语言

支持简体中文和英语。工作台语言选择器或 `ect.language` 设置支持
`auto`（默认，跟随 VS Code）、`zh-CN` 和 `en`。
工作台标签、连接状态、动态确认提示及配置对话框可即时切换，无需重新连接会话。
选择会保存到 VS Code 设置中，已有的工作区级设置优先。

命令标题及原生视图标题通过 `package.nls` 跟随 VS Code 显示语言，
不受工作台语言覆盖设置影响。用户的会话名称、命令名称、载荷、日志及底层驱动或网络诊断
不会被翻译。内部诊断探针仍包含英语技术输出。

通信运行于本机 UI Extension Host，远程工作区也遵循这一规则，
不会连接远程主机上的设备。工作区文件系统是否可访问取决于远程 URI 提供程序。

## 安全

通信操作要求工作区受信任。宿主会校验全部命令、长度及参数范围。
即使设置了控制信号，打开串口仍可能使开发板复位。串口自动重连要求序列号、
VID/PID 匹配且身份唯一；身份缺失或存在歧义时不会重连。

TCP/UDP 为明文通信。允许外部访问的监听及广播需要确认。
重新连接后不会自行恢复自动发送。TX 已写入仅表示本地写入完成，
不代表远端已收到或命令执行成功。TCP/串口数据块不等同于协议帧，UDP 不保证交付。

预览保留有界历史，每条记录最多显示 256 字节；原始日志保留完整载荷。
零长度 UDP 数据报会被录制并作为事件计数，但目前不会通过基于字节的预览 ACK 窗口推送。
TCP 部分广播失败会报告各客户端结果，但总 TX 字节计数目前不会统计部分失败广播中
已成功发送的那部分字节。

## 开发

使用 Node.js 22.11 或更高版本，先执行 `npm ci`，然后运行：

```powershell
npm run typecheck
npm test
npm run build
npm run package:vsix
npm run inspect:vsix
npm run probe:packaged
```

在 VS Code 中打开本目录，按 F5 启动开发扩展。
原生依赖位于宿主打包文件之外；插件用户无需运行 npm 或 node-gyp。
测试日志及下载缓存使用操作系统临时目录。
`scripts/preview.mjs` 中的 UI 预览桥仅用于测试，不包含在 VSIX 中。

在真实官方 VS Code Extension Host 中运行测试：

```powershell
$env:ECT_TEST_EXECUTABLE = "C:\Path\To\Code.exe"
npm run test:extension
```

未设置该变量时，测试运行器会下载 VS Code 1.95.0；
传入 `-- stable` 可选择稳定版。支持 `npm_config_https_proxy`。
测试使用隔离的用户目录和扩展目录。
