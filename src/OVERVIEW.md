# Embedded Communication Toolkit

> Windows x64 · VS Code 扩展 · 面向嵌入式开发与设备联调的本地通信工作台

**Embedded Communication Toolkit（ECT）** 是一个在 VS Code 内直接运行的通信调试扩展，提供**串口、TCP、UDP** 三类常用传输通道，并配套**多会话管理、自动发送、快捷命令、原始录制与数据导出**能力，方便你在写代码的同时完成板卡通信、固件联调、协议验证和接口抓包。

扩展全部运行在本机，不会上传任何通信内容到远端；默认不自动连接、不自动发送，需要你显式点击“打开/发送”才会执行操作，适合需要可控、可追溯的现场调试场景。

---

## 这个插件是干什么的

一句话：**在 VS Code 里像使用串口助手/TCP 调试工具一样，直接调通硬件和网络设备，并把结果记录下来**。

典型使用场景：

- **嵌入式固件调试**：通过串口读取启动日志、发 AT 指令、验证协议帧。
- **本地服务联调**：使用 TCP 客户端/服务端或 UDP 测试板卡、网关、上位机与本地进程的通信。
- **协议与接口验证**：HEX/ASCII 同时工作，支持时间戳、方向、计数、快捷命令，快速定位收发异常。
- **录制与留存证据**：将收发的原始字节按顺序写成 JSONL，可在不中断扩展的情况下导出 TXT/CSV 作为测试记录。

## 功能概览

### 1. 串口（Serial）

- 支持**自动枚举串口**或**手动输入串口路径**。
- 常用参数：波特率（300 ~ 2000000 常用预设 + 自定义）、数据位 7/8、校验、停止位。
- 支持 **DTR/RTS**、**RTS/CTS 流控**（具体能力取决于驱动与设备）。
- 发送端采用**有界串行队列**，支持 `write/drain` 等待，发送失败与超时会给出明确提示。
- 可选**自动重连**：串口设备按唯一身份匹配，手动关闭后停止重试。

### 2. TCP Client / TCP Server

- **TCP 客户端**：支持收发、超时、取消、有界串行发送与异常重连（指数退避 + 抖动）。
- **TCP 服务端**：最多同时接入 **16 个客户端**，每个客户端拥有唯一 `clientId`。
- 发送模式：可选**定向发送到单一客户端**，或**显式确认后广播**。
- 发送结果逐客户端返回：哪个成功、哪个失败、失败原因一目了然。

### 3. IPv4 UDP

- 支持**显式本地绑定地址/端口**、**显式远端地址/端口**。
- 单播与广播：发送广播需要**显式开启**，避免误发。
- 可配置**最大单报文载荷上限**，接收端保留**来源**与**报文边界**。

### 4. 多会话工作流

- 最多同时保留 **8 个会话**，每个会话独立缓存、队列、计数与重连状态。
- 支持 **创建 / 选择 / 打开 / 关闭 / 删除**，并在侧栏统一展示会话状态。
- 第 9 个会话会被拒绝创建，避免会话过多导致误操作。
- 关闭工作台编辑器面板后，会话、自动发送、录制仍继续运行；使用“断开全部连接”或停用来安全停止。

### 5. 接收与显示（HEX / ASCII / 时间戳）

- **接收显示与发送编码独立设置**：接收可用 HEX，发送可用 ASCII，互不影响。
- 显示字段：**UTC 时间戳、方向（RX/TX）、原始字节、文本视图**。
- 为避免 UI 卡顿，采用**虚拟化列表**，展示性能与数据量解耦。
- 搜索仅作用于显示文本（每条记录前 256 字节），不会修改原始录制数据。

### 6. 自动化发送

- **快捷命令**：保存、编辑、删除、一键执行，危险命令支持**二次确认**。
- **自动发送**：采用“完成后等待”的调度方式，最小间隔 50 ms，不会与手动发送重叠。
- 掉线后自动停止；**重连后不会自行恢复自动发送**，需你明确重新启用。

### 7. 配置与多语言

- 项目级配置：显式保存为工作区 `.vscode/ect.json`，带**版本号校验**和**覆盖确认**。
- 无工作区时使用扩展全局 `globalState` 存储；多根工作区会提示选择所属目录。
- 界面支持 **简体中文 / English**，命令标题通过 `package.nls` 跟随 VS Code 显示语言；工作台内部语言可单独切换。

### 8. 录制与导出

- 原始录制独立于预览写成 **JSONL**，附带全局有界队列、文件轮转、容量预算与不完整标记。
- 可导出为 **TXT / CSV**，导出前会先停止录制，拒绝导出“不完整”的源。
- CSV 导出包含**公式注入防护**，降低被下游表格软件误解释的风险。

## 细节说明

下面是你在 Marketplace 详情页“细节”区域最关心的一些实现要点：

### 工作区与信任

- 扩展属于 UI 类扩展（`extensionKind: ["ui"]`），默认仅在受信任工作区下完整启用通信能力。
- 不受信任工作区仅支持有限能力，避免被潜在恶意工作区自动连接本地串口或网络。
- 虚拟工作区（`virtualWorkspaces`）暂不支持。

### 安全与可控性

- **创建会话不会自动连接**，必须手动点击“打开”。
- **自动发送默认关闭**，必须手动启用；会话断开后立即停止。
- TCP Server 的广播、快捷命令中的危险操作，都需要**显式确认**。
- 现有日志文件不会被静默覆盖；导出、录制都强制要求新文件路径。

### 性能与可靠性

- 发送走有界队列 + 串行执行，避免串口/网络接口被瞬时风暴打爆。
- 接收预览与原始录制解耦：显示慢不影响写盘；丢预览也不会丢原始记录。
- 自动重连采用**指数退避 + 抖动**，最多 10 次，防止故障时产生重试风暴。

### 平台与运行要求

- 预打包平台：**Windows x64**（Marketplace 下载后，该包面向 `win32-x64`）。
- VS Code 版本：`^1.95.0`。
- Node 开发构建要求：`>= 22.11.0`（使用者从 VSIX 安装无需 Node）。
- 串口能力依赖 `serialport` 原生模块，已随 VSIX 打包，无需单独构建。

### 界面布局

- 顶部：会话选择、打开/关闭/删除、重连、状态，控件统一高度，窄面板时可横向滚动。
- 主体：顶部参数区（串口/TCP/UDP），左侧接收日志，右侧发送区 + 快捷命令，底部计数/显示选项。
- TCP Server 发送目标被移动到**发送区**，避免在狭窄顶部栏里误选客户端。
- 颜色统一使用当前 VS Code 主题色，原生控件随浅色/深色/高对比度主题切换。

## 快速开始

1. 在 VS Code 中安装 `ect-toolkit-*.win32-x64.vsix`（扩展视图 → 右上角“…” → Install from VSIX…）。
2. 运行命令：**ECT: Open Communication Workbench（ECT：打开通信工作台）**。
   - 也可点击活动栏中的**通信**图标，在“连接”视图中打开工作台入口。
3. 创建会话：选择 **Serial / TCP Client / TCP Server / UDP**，填写参数并保存。
4. 选中会话，点击**打开**；进入发送区后可：
   - 手动发送 HEX 或 ASCII；
   - 新建并保存快捷命令；
   - 开启自动发送（需先设置间隔与内容）；
   - 开启录制并在完成后导出 TXT/CSV。
5. 所有会话结束后，可使用命令 **ECT: Disconnect All Sessions（ECT：断开全部会话）** 一次性清理。

## 支持与反馈

如遇到枚举不到串口、TCP 广播失败、CSV 内容异常、界面布局在你的分辨率下错乱等问题，可以先执行 **ECT：运行环境与工作区诊断**（`ECT: Runtime and Workspace Diagnostics`）查看本机环境提示，再结合扩展日志补充反馈。
