## 1. 使用规则

- 阶段编号沿用原方案：Phase 0 风险原型、Phase 1 纵向链路、Phase 2 通信与多会话、Phase 3 配置与录制、Phase 4 发布候选。
- 优先级 P0 表示启动开发前必须解决的阻塞风险；P1 表示 MVP 必须交付；P2 表示后续版本。P0 不表示功能重要性高于所有 P1。
- 下列路径是建议交付路径，不表示文件已经存在；可在脚手架冻结时调整。
- 负责人初始未分配；单人开发时可由同一人承担，不以岗位数量推断团队人数。
- 状态建议使用：待开发、开发中、待验证、已完成、阻塞。只有交付物和验收证据齐备才能标为已完成。
- 具体库版本、最低 VS Code 版本及性能预算在 Phase 0 验证后冻结；新增加的工具建议不能视为原方案已决定的选型。
- 本表不修改原方案。遇到冲突时先更新决策记录，经确认后同步两个文档。

| UDP | Node.js `dgram` | IPv4 单播、广播、监听 | 保留 datagram 与来源；不保证交付，不自动分片/拼帧 | 已定 |

| 日志存储 | JSONL、异步文件写入 | 原始字节与元数据录制 | 有界队列、轮转、错误/不完整标记；TXT/CSV 从同一记录导出 | 已定 |
| 单元与接口测试 | TypeScript 测试框架，建议评估 Vitest 或 Node.js test runner | 状态机、Codec、Schema、队列、回环 | 可控时钟；mock 串口不能代替硬件测试 | 框架待确认 |

## 4. 核心数据与接口表

| 对象 | 必需信息或行为 | 边界与约束 | 对应任务 |
| --- | --- | --- | --- |
| TransportConfig | `kind` 对应的串口/TCP/UDP 配置联合类型 | 禁止用大量可选字段模糊不同接口；运行时校验 | T07、T26 |
| Transport | open、close、send、subscribe、status、dispose、capabilities | 幂等、取消、可释放订阅、稳定错误码；不直接暴露给 UI | T07～T09、T17～T19 |
| ReceiveEvent | 原始 Buffer、时间、stream-chunk/datagram、clientId/remote | Buffer 仅在 Host 内部；UDP 保留边界；TCP/Serial 不伪造报文 | T07、T29 |
| SendTarget | client、broadcast、udp 三类显式目标 | Serial/TCP Client 禁止目标；Server 必须选择；UDP 可用验证后的会话远端 | T18、T19、T22 |
| SendResult | 本地 acceptedBytes、逐客户端结果/错误 | 不表示远端收到或命令成功；失败/部分/未知结果分开 | T22、T29 |
| SessionRuntime | status、generation、句柄、队列、计数器、任务 | 由 SessionManager 所有；不写入项目配置 | T08、T20、T21 |
| Webview 命令 | version、requestId、type、操作需要的 sessionId、合法参数 | 会话操作校验 session；ready/全局动作的结构在 Schema 冻结时单独定义 | T10 |
| Webview 数据批次 | sessionId、序号、时间、方向、peer、base64 原始载荷 | 仅传可序列化 DTO；ACK、缺口、快照和增量语义明确 | T10、T15 |
| JSONL 记录 | schemaVersion、sessionId、sequence、UTC、direction、peer、字节长度、base64、结果/错误 | 来源与发送状态可追溯；记录不依赖显示格式 | T29、T30 |
| 项目配置 | version、会话配置、快捷命令及必要引用 | URI 隔离、显式保存、不自动动作；完整 Schema 在 T26 交付 | T26、T27 |

| A08 | 导出安全与一致性 | 引号/换行、公式样式字段、非法路径消息 | TXT/CSV 与记录一致；正确转义/防公式注入；路径仅由 Host 选择 | T31、T32 |

| A13 | 扩展与平台兼容 | 最低/稳定 VS Code、Windows x64、SSH/WSL/容器工作区 | 本机 Host 路径明确；最低版本可用；远程配置不可用时明确降级 | T03、T34 |
| A14 | 离线安装与产物 | 无开发工具/源码目录的干净机器安装最终 VSIX | 原生依赖齐全、真实串口可用、无联网安装步骤；网络不被串口加载错误拖垮 | T02、T35、T36 |

UDP 的网络丢包、乱序和重复需用源端序号评估，不能仅凭应用字节计数证明零丢包。强制退出前的最后一批日志不作落盘保证。上述性能指标均须记录测试机器和测量方式，不能直接视为认证结果。
